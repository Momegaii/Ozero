## 1. Decision

A1 **accepts IF-008 v1.1** as the Stage 1 DMA/platform interface at A3
`b9a69d8`. The reviewed `include/ozero/platform.h` and `include/ozero/block.h`
match A1's conditions, and A3's copies of A1's ten public headers are
byte-identical to A1 `30ee4f0`.

This is A1's final interface sign-off. It is **not** hardware validation, not a
runtime DMA test, and not Stage 0 acceptance. The AHCI probe remains blocked
until:

1. the director approves D-007, and
2. A3 accepts the conditions in §6 and corrects the non-blocking deltas in §5.

## 3.1 A3 review-packet confirmations

A3 published `docs/interfaces/IF-008-v1.1-a1-review-packet.md` at `2dcc0fc`
and asked A1 to confirm eight invariants. A1 confirms them against the reviewed
headers at `b9a69d8`:

| # | A3 invariant | A1 confirmation |
|---|---|---|
| 1 | One embedded `o0_io_request` per block request | Confirmed. `struct o0_bio` embeds `struct o0_io_request io`; no second request object. |
| 2 | No scatter-gather pointer in the generic request | Confirmed. `o0_io_request` has one contiguous buffer; `o0_bio_vec` is A3 logical-page metadata, not a hardware SG list. |
| 3 | Transfers above `max_segment` split into multiple buffers and requests | Confirmed. A3 splits at the block layer; A1 does not add an SG pointer. |
| 4 | A3 implements A1's `struct o0_device_ops` exactly | Confirmed for the reviewed headers; `platform.h` includes A1's `driver.h` and declares no competing device type. |
| 5 | CPU `void *` addresses stay distinct from device-visible `o0_paddr_t` | Confirmed. `o0_dma_buffer` carries `void *vaddr` and `o0_paddr_t paddr`; no `dma_addr_t`/`iova_t`. |
| 6 | `io_submit` completion does not occur before the call returns | Confirmed as an interface obligation; A3 defers synchronous completion. Runtime unverified. |
| 7 | Reset invalidates requests and device state but does not free A1 DMA buffers or unmap BARs | Confirmed. A1 owns quiesce/reset; A3's `o0_block_ops.reset` is block-layer recovery after A1's reset. |
| 8 | AHCI and real DMA work stay blocked until A1 signs this exact version | A1 signed `b9a69d8`; A3 accepted at `307b919`. AHCI remains blocked on D-007 and D-021; no runtime proof exists. |

A3's packet also notes that `docs/a3-dma-contract.md` was stale. It now records
the IF-008 v1.1 acceptance and the D-007/D-021 gate.

4. **A4 `CODEOWNERS`: resolved at `b4232a0`.** File-level entries cover

5. **`o0_block_geometry.max_segments` needs a comment.** It is an A3 logical-bio
   limit, not an A1 hardware SG capability. This is a documentation clarification
   in `block.h`; it does not block the interface and does not change the accepted
   header blob.

## 6. Conditions A3 accepted at `307b919`

1. `dma_constraints` fills `addr_mask` as a contiguous low-bit mask,
   `max_segment` as bytes per physically contiguous segment, and `coherent`
   truthfully. A1 never infers them from a device class.
2. `dma_quiesce` stops new DMA, waits for in-flight requests, is idempotent, and
   does not free A1 buffers.
3. `reset` runs only after quiesce and after requests complete or are cancelled.
   It does not free A1 DMA buffers or unmap BARs; A3 reinitialises.
4. `io_submit` does not complete before `o0_io_submit` returns. Synchronous
   completion is deferred.
5. `io_cancel` is best-effort; `O0_EBUSY` means completion will still run.
6. BARs are accessed only through `o0_device_map_bar`, as UC/NX mappings, never
   through the HHDM.
7. A transfer larger than `max_segment` is split into multiple `o0_dma_buffer`
   objects and multiple `o0_io_request` objects. No SG pointer is added to
   `o0_io_request`.
8. Stage 1 DMA is trusted ring-0 only. No userspace or untrusted driver DMA
   before an IOMMU domain exists.

A3's acceptance is recorded in
`a3/docs/interfaces/IF-008-v1.1-acceptance.md` at `307b919`: all eight conditions
accepted, with D-007/D-021 and the AHCI probe still blocked.

## 7. What this decision does not mean

- It does not approve D-007 or D-021; the director still owns both decisions.
- It does not prove AHCI, DMA, interrupt routing, reset or BAR mapping at runtime.
- It does not accept A3's block-layer implementation; none exists yet.
- It does not accept Stage 0.

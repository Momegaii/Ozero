## 1. Decision

A1 **accepts IF-008 v1.1** as the Stage 1 DMA/platform interface at A3
`b9a69d8`. The reviewed `include/ozero/platform.h` and `include/ozero/block.h`
match A1's conditions, and A3's copies of A1's ten public headers are
byte-identical to A1 `30ee4f0`.

This is A1's final interface sign-off. It is **not** hardware validation, not a
runtime DMA test, and not Stage 0 acceptance. The AHCI probe remains blocked
until:

1. the director approves D-007, and
2. A3 accepts the conditions in §6 and corrects the non-blocking deltas in §5.

## 4. A1 condition validation

| A1 condition | A3 evidence | Result |
|---|---|---|
| Include A1 headers, no redeclaration | `platform.h` includes `<ozero/types.h>`, `status.h`, `irq.h`, `mm.h`, `driver.h`; `block.h` includes `platform.h` | Pass |
| No DMA domain, IOMMU, IOVA or translated address type | A3 tests assert the absence of `o0_dma_domain`, `dma_map_sg`, `dma_map_single`, `iommu_map`, `dma_domain_t`, `iommu_domain_t`, `iova_t`, `dma_addr_t` | Pass |
| `block.h` uses `struct o0_io_request` | `struct o0_bio` embeds `struct o0_io_request io`; `io.complete` is the only A1 completion callback | Pass |
| No SG pointer in `o0_io_request` | A3 documents one contiguous buffer per request and splits larger transfers; `o0_bio_vec` is explicitly logical pages, not hardware SG | Pass |
| No implicit 32-bit DMA assumption | Constraints are supplied by A3's `dma_constraints`; no fixed mask in the headers | Pass |
| Reset does not assume buffers/BARs survive | `block.h` reset callback resets A3 protocol state only; IF-008 says A1 quiesce/reset does not free buffers or unmap BARs | Pass |
| No BAR access through the HHDM | IF-008 and driver draft require `o0_device_map_bar`, UC/NX, never HHDM | Pass |
| Completion after `o0_io_submit` returns | IF-008 and driver draft state the rule; synchronous completion must be deferred | Pass |
| Quiesce before free/unmap/reset | IF-008 consumer obligations 6 and 7; driver draft §9 | Pass |
| Trusted ring-0 DMA only | IF-008 consumer obligation 9; no userspace DMA path | Pass |

## 5. Remaining deltas (non-blocking)

These do not change the accepted headers. They must be corrected before merge:

1. **A3 IF-008 document is stale on D-009/XB-007.** It says A4's register records
   `include/o0/` as approved. A4 `245007d` approves `include/ozero/` (D-009) and
   closes XB-007. A3 must update the "Open cross-agent dependencies" section. The
   status lines in A3's IF-008 document, `docs/04-driver-interface-draft.md`,
   `README.md`, `EVIDENCE.md` and `AGENTS.md` still say A1 approval is pending; A3
   must update them to "A1 accepted at `b9a69d8`" after accepting the conditions.
2. **A4's interface registry is stale.** At `245007d` and again at `3ae7aca`,
   IF-008 is still `1.1` with `A1 final approval pending` or `0.1 draft` depending
   on the file. A4 must update the row to `1.1`, owner A3, status `A1 accepted at
   b9a69d8; director D-007 pending`.
3. **A3 vendors A1's headers.** The ten copies are byte-identical today. A3 must
   not modify them; on merge, A1's headers at `30ee4f0` or later win. A3 must
   rebase on the A1 branch before merge.
4. **A4 `CODEOWNERS` must cover the two A3 headers.** A1 owns
   `include/ozero/{boot,cpu,driver,ipc,irq,mm,o0,status,thread,types}.h`. A3 owns
   `include/ozero/platform.h` and `include/ozero/block.h`, with A1 review. A4 must
   add file-level entries; the directory-level `/include/ozero/` rule alone is
   not sufficient.
5. **`o0_block_geometry.max_segments` needs a comment.** It is an A3 logical-bio
   limit, not an A1 hardware SG capability. This is a documentation clarification
   in `block.h`; it does not block the interface.

## 6. Conditions A3 must accept

1. `dma_constraints` fills `addr_mask` as a contiguous low-bit mask,
   `max_segment` as bytes per physically contiguous segment, and `coherent`
   truthfully. A1 never infers them from a device class.
2. `dma_quiesce` stops new DMA, waits for in-flight requests, is idempotent, and
   does not free A1 buffers.
3. `reset` runs only after quiesce and after requests complete or are cancelled.
   It does not free A1 DMA buffers or unmap BARs; A3 reinitialises.
4. `io_submit` does not complete before `o0_io_submit` returns. Synchronous
   completion is deferred.
5. `io_cancel` is best-effort; `O0_EBUSY` means completion will still run.
6. BARs are accessed only through `o0_device_map_bar`, as UC/NX mappings, never
   through the HHDM.
7. A transfer larger than `max_segment` is split into multiple `o0_dma_buffer`
   objects and multiple `o0_io_request` objects. No SG pointer is added to
   `o0_io_request`.
8. Stage 1 DMA is trusted ring-0 only. No userspace or untrusted driver DMA
   before an IOMMU domain exists.

## 7. What this decision does not mean

- It does not approve D-007 or D-021; the director still owns both decisions.
- It does not prove AHCI, DMA, interrupt routing, reset or BAR mapping at runtime.
- It does not accept A3's block-layer implementation; none exists yet.
- It does not accept Stage 0.

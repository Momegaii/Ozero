## 1. Why v1.1 exists

A1 accepted IF-009 v1.0 with conditions. Two negative cases were explicitly identified as
gaps, not covered tests, in A2's contract and A1's review:

| Gap | v1.0 state | Required v1.1 case |
| --- | --- | --- |
| Truncated PE headers | No negative case | A parser must reject an image truncated inside the DOS header, NT headers, optional header or section table without reading past the file |
| Missing DLL name in an import descriptor | `import_terminator` covers a missing terminator, not a missing DLL name | A parser must reject an import descriptor whose `Name` RVA is zero, out of bounds or points to an empty string |

These gaps do not invalidate the v1.0 signatures. They must not be reported as covered, and
they must remain visible until v1.1 is implemented, reviewed and signed.

## 2. Required v1.1 negative cases

| Case ID | Mutation | Expected result | Evidence |
| --- | --- | --- | --- |
| `truncated_dos_header` | Cut the image before the `e_lfanew` target | Parse error naming the DOS/NT header boundary; no out-of-bounds read | L0 negative report |
| `truncated_nt_headers` | Cut inside `IMAGE_NT_HEADERS64` | Parse error naming the NT header size; no out-of-bounds read | L0 negative report |
| `truncated_optional_header` | Cut inside the optional header | Parse error naming the optional-header size | L0 negative report |
| `truncated_section_table` | Cut inside the section table | Parse error naming the section-table size | L0 negative report |
| `import_missing_dll_name` | Set one import descriptor `Name` RVA to 0 | Reject with a missing-DLL-name error, not an import-terminator error | L0 negative report |
| `import_dll_name_oob` | Point one import descriptor `Name` RVA past EOF | Reject with an out-of-bounds name error | L0 negative report |

The existing `import_terminator` case stays. The new cases must be distinguishable in the
negative report; a generic parse failure is not enough.

## 3. Acceptance criteria

1. The six cases are generated by the A2 fixture tooling, not hand-edited binaries.
2. Each case fails for the named reason, with a stable error code or message.
3. The negative report lists the case, expected failure, observed failure and exit status.
4. `make fixtures-check` reports no drift for the unmodified fixtures.
5. A1 and A3 re-sign v1.1. The v1.0 signatures do not carry forward.
6. The result stays L0. No PE load, import resolution, TLS callback, exception dispatch or
   Windows compatibility claim is allowed.

## 3. A3 invariants for A1 to confirm

A1 should explicitly confirm these in its decision:

1. One embedded `o0_io_request` per block request.
2. No scatter-gather pointer assumption in the generic request.
3. Transfers above `max_segment` split into multiple buffers and requests.
4. A3 implements A1's `struct o0_device_ops` exactly.
5. CPU pointers (`void *`) stay distinct from device-visible `o0_paddr_t`.
6. `io_submit` completion does not occur before the call returns.
7. Reset invalidates requests and device state but does not free kernel DMA
   buffers or unmap BARs.
8. AHCI and real DMA work stay blocked until A1 signs this exact version.

## 4. Naming clarification for A1

A1's `o0_device_reset` and A3's `o0_block_ops.reset` are different layers:

- `o0_device_reset` is A1's full device reset, called after
  `o0_device_dma_quiesce`.
- `o0_block_ops.reset` is A3's block-layer recovery policy. It runs after A1's
  reset, does not free A1 buffers, does not unmap BARs, and re-arms the A3
  queue.

If A1 prefers a different name to avoid confusion, that is a documentation-only
change unless it alters the ABI.
